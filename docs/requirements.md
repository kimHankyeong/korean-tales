# Korean Tales 게임 개발 요구사항 정리

> 기획서 원문을 기능 단위로 분해해 클로드 코드에 입력하기 쉬운 형태로 재구성했습니다.
> 미확정 사항은 맨 아래 "결정 필요 사항"에 따로 모아뒀습니다.

---

## 1. 방(로비) 설정 기능

- [ ] 인원수 모드: **6인 모드 / 9인 모드** 선택 가능한 방 생성 UI
- [ ] 개인 발언시간 옵션: **80초 / 120초** 중 방장이 선택
- [ ] 전체 토론시간 옵션: **3분 / 5분** 중 방장이 선택
- [ ] 개인 발언 중 **Skip 버튼**: 본인 발언 종료 시 다음 순서로 즉시 넘김
- [ ] 전체 토론 중 **Skip 시스템**: 생존자 전원이 skip을 누르면 토론 종료 → 투표 단계로 자동 전환

## 3. 캐릭터 & 스킬 시스템

공통: 각 캐릭터는 배경설화(1~2줄) + 스킬 설명을 **스킬북 UI**에 함께 표시.

### 악 진영
| 캐릭터 | 스킬명 | 효과 | 비고 |
|---|---|---|---|
| 저승사자 | 저승길 동무 (2회) | 전날 밤 미리 길동무 1인 지정 → 투표·처형 등으로 자신이 사망 시 지정한 사람과 함께 죽음. 2회 지정 후에도 사망하지 않았다면 스킬 종료 | 기존 "사자의 명부(예고킬)"에서 교체 — 밸런스 사유. 죽은 자를 저승으로 인도하는 본연의 설화와 부합 |
| 깡철이 | 재앙무죄 (패시브) | 해태의 투사에 **"악 진영이 아닙니다"**로 표시됨. 별도 발동 절차 없음 | 배경설화: 용이 되지 못하고 추락한 이무기. 지나는 하늘 아래는 비가 마름. 재앙에는 죄를 물을 수 없기에 해태의 심판이 닿지 않음 |
| 구미호 | 유혹 (1회) | 전날 밤 사용 여부 결정 → 다음날 낮 투표를 통째로 스킵 | 조사 회피 능력은 깡철이로 이전, 투표 스킵만 보유 |

### 선 진영
| 캐릭터 | 스킬명 | 효과 | 비고 |
|---|---|---|---|
| 자청비 | 부활꽃 / 멸망꽃 (각 1회) | **아침에 사용.** 부활꽃: **그날 밤 악 진영의 킬로 사망한 사람만** 되살릴 수 있음(치유). 멸망꽃: 1인을 즉시 처형. 각각 게임당 1회씩, **같은 아침에 두 꽃 동시 사용 불가** | 부활꽃 제외 대상: 저승길 동무·피 맺힌 유서로 동반 사망한 사람, 낮 투표 처형자. 멸망꽃 킬은 도깨비 장난으로 막을 수 없고, 멸망꽃 사망자는 동귀어진류 스킬 사용 불가 |
| 해태 | 투사 | 밤에 1인 지목 → **"n번은 악 진영입니다 / 악 진영이 아닙니다"** 형식으로 결과 표시. 단, 깡철이는 "악 진영이 아닙니다"로 표시됨 | ✅ **확정(고정) — 변경하지 않음** |
| 도깨비 | 도깨비 장난 (1회) | **그날 밤 악 진영의 킬을 무산시킴.** 단, 아침의 자청비 멸망꽃 킬은 막지 못함 | 밤에 사용 여부 결정. 악 투표 진행 여부·차단 사실 공개 여부는 세부 결정 필요 |
| 장화홍련 | 피 맺힌 유서 (1회) | **자신의 사망이 확정된 시점**에 1인을 지목해 함께 데려감(동귀어진). 10초 내 미선택 시 자동 포기, "스킬 포기" 버튼으로도 포기 가능 | 자청비의 멸망꽃으로 사망한 경우 스킬 사용 불가 |

### 중립
| 캐릭터 | 스킬명 | 효과 |
|---|---|---|
| 바리공주 | 연민 (자동 발동) | **까치선비가 어떤 방식으로 사망하든** 부활 가능 — 저승길 동무·피 맺힌 유서 동반사망 등 자청비 부활꽃이 닿지 않는 죽음에도 예외적으로 적용. 낮 사망이면 당일 아침, 그 외에는 다음날 아침 자동 부활 |
| 까치선비 | 없음 | 선 진영 소속 중 사망하면 중립 전환. 바리공주 생존 시 부활 대상이 됨 |

- [ ] **부활자 공통 규칙**: 부활꽃·연민으로 되살아난 사람이 이미 사용한 1회성 스킬은 **소모된 상태로 유지**(복구되지 않음)

## 4. 밤 페이즈 진행 로직

1. 해태 / 도깨비 스킬 사용 시간 (10초, 동시 진행)
2. 악 진영 토론 (90초)
3. 악 진영 처치 대상 투표 (10초)
4. 도깨비가 "도깨비장난"을 사용한 밤이면 → 악 진영의 킬 결과 무효 처리. **악 진영에게 차단 사실을 따로 알리지 않으며**, 다음날 아침 전체에게 "사망자 없음"으로만 표시
5. 악 진영 개별 스킬 시간 (10초, 투표 후 순차 또는 동시)
   - 저승사자: 사망 시 데려갈 길동무 선택 (저승길 동무)
   - 구미호: 다음날 낮 투표 스킵 사용 여부 결정 (유혹)
   - 깡철이: 패시브라 선택 절차 없음

---

## 5. 낮 페이즈 진행 로직

1. 낮 시작 직후 (10초): 자청비에게 부활꽃/멸망꽃 사용 선택지 표시
   - 부활꽃: 그날 밤 악 진영 킬 사망자가 있을 때만 활성화, 대상 지정 부활 (동반사망자·투표 처형자는 대상 아님)
   - 멸망꽃: 생존자 1인 지정 즉시 처형 (도깨비 장난으로 방어 불가)
   - 같은 아침에 둘 다 사용 불가 (하나 선택 시 다른 쪽 비활성화)
2. 구미호가 전날 밤 "유혹"을 사용했다면: 낮 토론 후 투표 단계 전체 스킵 → 바로 밤 전환
3. 낮 토론 (전체 토론시간 옵션에 따름)
4. 투표 진행
   - **기권 규칙**: 투표권을 가진 생존자 전원이 기권하면 희생자 없이 밤으로 전환. 단 한 표라도 득표자가 있으면 최다 득표자가 처형됨 (기권표가 다수여도 무관)
   - **동표 처리**: 최다 득표가 동률이면 → 최다득표자 전원에게 동시 발언 시간 20초 부여 → 재투표 진행 → 재투표에서도 동표면 최다득표자 중 **무작위 1인 처형**
5. **최후의 변론 (20초)**: 투표로 처형 대상이 확정되면 그 사람에게만 채팅 입력 권한 부여, 나머지는 관전. Skip 버튼으로 조기 종료 가능
6. 사망 확정 트리거 (투표·멸망꽃 등 사망 발생 시 공통 처리):
   - 저승사자 사망 시: 지정해둔 길동무와 동반 사망 → 결과 표시 후 프로필 변경 전 저승사자 전용 사망 이펙트 재생
   - 장화홍련 사망 시: "피 맺힌 유서" 대상 선택창 10초 표시 (멸망꽃 사망이면 미표시)
   - 조언자 사망 시: 승계 지목 / 파기 선택창 10초 표시
   - 까치선비 사망 시: 바리공주 생존 중이면 "연민" 자동 부활 예약 (사망 원인 불문)

## 6. UI/UX 요구사항

- [ ] **낮 표시 애니메이션**: 해 모양 아이콘이 나타났다가 채팅창의 "낮" 텍스트 옆으로 이동/고정
- [ ] **발언 순서 표시 포맷**: `(해)낮-개인발언시간-1번` 형태로 채팅창에 표시
- [ ] **카운트다운 표시**: `토론 시간 00초 남음` / `개인 발언 시간 00초 남음` 문구
- [ ] **투표 창**: 화면 중앙, 화면 1/6 크기, 생존 플레이어 번호+프로필 가로 나열. 프로필 클릭 → 하단 "투표하기" 버튼 활성화. **기권 옵션 포함**
- [ ] **스킬 사용 창**: 투표 창과 동일 레이아웃, 버튼만 "선택하기"로 대체 (대상: 해태, 자청비, 저승사자, 장화홍련(사망 시) 등. 장화홍련 창에는 "스킬 포기" 버튼 추가)
- [ ] **메모장**
  - 모바일: 채팅창 뒤에 숨겨져 있다가 클릭 시 앞으로 슬라이드
  - PC: 채팅창 옆에 상시 노출 (동시 열람 가능)
- [ ] **직업 설명 버튼** (우측 상단): 클릭 시 9개 캐릭터 스킬북 + 진영별 승리 조건 표시
- [ ] **플레이어 목록 패널** (우측): 화면 1/6 크기, 프로필 + 배정 번호 표시
- [ ] **투항하기 버튼**
  - 클릭 시 확인 모달: "정말로 포기하시겠습니까?" 예/아니오
  - **팀 동시 투항 방식**: 최초로 투항을 누른 시점부터 30초 카운트 시작 → 30초 내에 같은 팀 생존자 전원이 투항을 누르면 게임 종료(상대 팀 승리) → 30초가 지나도 전원 동의가 안 되면 투항 진행 종료(게임 계속)
  - 투항 진행 중이라는 사실이 상대 팀에게 노출되지 않도록 처리
- [ ] **악 팀 전용 버튼 (P버튼)**: 투항 버튼 옆 "원 안에 P" 아이콘. 클릭 시:
  - 사용자 본인 즉시 사망 처리
  - 해당 낮의 투표 단계를 스킵
  - 바로 밤 페이즈로 전환
  - (확인 모달 필요 여부는 투항 버튼과 동일하게 적용할지 별도 검토)

## 7. 발언 순서 결정 로직 — "조언자 출마" 시스템

**첫날 아침 (조언자 선출):**
1. 조언자 출마 버튼 표시 (7초) — 원하는 유저는 이 시간 안에 출마 신청
2. 출마자 개인별 어필 발언 (각 20초)
3. 전체 토론 (50초)
4. 조언자 선출 투표 (7초) — **출마한 유저에게는 투표권 없음**
5. 최다 득표자가 조언자로 확정

**조언자 규칙:**
- 조언자는 **방울**(무당의 무구)을 상징물로 가짐
- 조언자의 발언 순서는 매일 **제일 마지막**
- 매 아침, 조언자가 자신의 앞뒤 번호를 기준으로 **역순 / 정순** 중 그날의 발언 방향을 결정
- **선출 동표 처리**: 최다 득표가 동률이면 해당 최다득표자들만 후보로 하여 재투표 → 재투표에서도 동표면 최다득표자 중 **무작위 선정**

**조언자 사망 시 (사망 확정 트리거, 10초):**
- 죽기 전 두 가지 중 선택:
  - **승계**: 생존자 중 번호를 지목해 방울(조언자 역할)을 넘겨줌
  - **파기(방울 깨뜨리기)**: 조언자 역할 소멸 → 이후 발언 순서는 앞번호부터 정순으로 고정 진행
- **10초 내 미선택 시 자동 파기(소멸)** 처리

## 8. 승리 조건

- **악 진영 승리**: 선 진영 전원 탈락 **또는** 선 진영 전원이 항복 투표
- **선 진영 승리**: 악 진영 전원 탈락 **또는** 악 진영 전원이 항복 투표
- [ ] 항복(투항)에 의한 승리 조건은 **일차(day count)와 무관하게 언제든 성립** — 기존 "4일차 이후"라는 제한 삭제. 탈락에 의한 승리 조건도 동일하게 일차 제한 없음

## 10. 클로드 코드 프롬프트 순서

> 사용법: 이 md 파일을 프로젝트 폴더(예: `docs/requirements.md`)에 넣어두고, 아래 프롬프트를 순서대로 하나씩 클로드 코드에 입력하세요. 각 프롬프트는 이전 단계 결과물이 있다는 전제로 작성되어 있습니다.

**1단계 — 프로젝트 초기 세팅**
```
docs/requirements.md를 읽고 korean_tales 채팅형 소셜 디덕션 게임 프로젝트의 기본 구조를 잡아줘.
프론트: [사용할 프레임워크 명시, 예: React + TypeScript]
백엔드/실시간 통신: [예: Node.js + Socket.io, 또는 Firebase]
아직 코드는 작성하지 말고, 폴더 구조와 사용할 기술 스택만 제안해줘.
```

**2단계 — 캐릭터/스킬 데이터 모델**
```
docs/requirements.md의 3번 섹션(캐릭터 & 스킬 시스템) 표를 기반으로 캐릭터와 스킬의 데이터 모델을 TypeScript 인터페이스로 정의해줘.
- 진영(악/선/중립), 스킬 사용 횟수 제한, 사용 가능 시점(밤/아침/사망확정시), 패시브 여부를 필드로 포함해줘.
- 9개 캐릭터(저승사자, 깡철이, 구미호, 자청비, 해태, 도깨비, 장화홍련, 바리공주, 까치선비) 인스턴스 데이터도 같이 만들어줘.
```

**3단계 — 게임 상태 머신(FSM)**
```
docs/requirements.md의 4번(밤 페이즈), 5번(낮 페이즈), 7번(조언자 출마 시스템) 섹션을 기반으로 게임 전체 상태 머신을 설계하고 구현해줘.
첫날 아침의 조언자 선출 단계, 이후 매일 반복되는 낮/밤 사이클, 사망 확정 트리거(저승사자/장화홍련/조언자/까치선비)까지 전부 상태로 표현해줘.
각 상태 전이 조건과 다음 상태를 주석으로 명시해줘.
```

**4단계 — 타이머 시스템**
```
docs/requirements.md의 2번 섹션 타이머 표를 기반으로, 서버 권위(server-authoritative) 타이머 시스템을 구현해줘.
클라이언트에는 카운트다운 UI만 동기화하고, 실제 시간 판정은 서버에서 하도록 해줘.
Skip 버튼으로 타이머를 조기 종료시키는 기능도 포함해줘 (개인 발언, 전체 토론에 적용).
```

**5단계 — 투표 / 스킬 선택 공용 UI**
```
docs/requirements.md의 6번 섹션 UI 요구사항을 기반으로, 투표 창과 스킬 사용 창을 공용 컴포넌트로 만들어줘.
레이아웃은 동일하게 하고 버튼 텍스트만 "투표하기"/"선택하기"로 분기해줘.
기권 옵션, 스킬 포기 버튼(장화홍련·조언자용)도 옵션으로 켤 수 있게 만들어줘.
```

**6단계 — 투표 결과 판정 로직**
```
docs/requirements.md의 5번 섹션의 기권 규칙과 동표 처리 로직을 구현해줘.
- 전원 기권 시 무처형
- 동표 시 최다득표자 20초 발언 후 재투표
- 재투표 후에도 동표면 무작위 처형
조언자 선출 투표(7번 섹션)에도 같은 동표 처리 로직을 재사용해줘.
```

**7단계 — 승리 조건 판정**
```
docs/requirements.md의 8번 섹션 기반으로 승리 조건 판정 로직을 구현해줘.
탈락에 의한 승리, 투항에 의한 승리(6번 섹션의 30초 팀 동의 메커니즘) 둘 다 일차와 무관하게 매 순간 체크되도록 해줘.
```

**8단계 — 부속 UI (메모장 / 스킬북 / 투항 / P버튼)**
```
docs/requirements.md의 6번 섹션 나머지 항목을 구현해줘: 메모장(모바일 슬라이드 / PC 상시노출), 직업 설명 스킬북 모달, 투항 버튼(30초 팀 동의), 악 팀 전용 P버튼(즉시사망+투표스킵+밤전환).
```

**9단계 — 통합 테스트 및 밸런스 점검**
```
지금까지 구현한 걸 9인 모드 기준으로 한 판을 시뮬레이션하는 테스트 스크립트를 만들어줘.
각 캐릭터 스킬이 최소 한 번씩은 발동되는 시나리오로 구성하고, docs/requirements.md의 규칙과 실제 동작이 일치하는지 확인해줘.
```
